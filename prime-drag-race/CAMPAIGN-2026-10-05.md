## Causes

- **Lane divergence was the main cost (C5).** INFERRED, high confidence, from the A/B: the old mark loop
  ran `while j < 32`, a branch whose trip count differs per lane, and the emitter places no reconvergence
  point. Making the trip count depend only on the prime (the same for every active lane) gave 7.81x with
  nothing else changed. GPT-6 Astra's cycle model predicted this before the run: the fixed-stall critical
  path is about 30 to 60 us per launch, far below the measured 821 us, while fully serialized lanes land
  near the measured times (`astra/REPORT.md`).
- **Not enough parallel work (C1).** OBSERVED: 1.79x lower kernel time for 1.92x more threads. The I42
  64-CTA cap did not reproduce up to 1024 CTAs.
- **Host wait, not the chip, made the launch floor (C4).** OBSERVED in the diagnostic tool: an empty
  launch took 103 us with the sleep-poll and 6 us with the spin. Run-to-run spread also fell about 10x.
- **Fixed stall counts are not the bottleneck (C2b).** OBSERVED 1.02x, as Astra's model predicted.
- **Table loads were not the bottleneck (C3).** OBSERVED: shared memory made it slower. This refuted the
  earlier inference from C2a. The cause of C3's extra ~97 us per launch at 64 CTAs is UNKNOWN; a changed
  shared-memory carveout is ruled out (QMD min/max/target unchanged, DOCUMENTED in Astra's report).
- **The best table placement depends on the launch configuration (C7).** OBSERVED, one binary, only the
  table mode changed, A-B-A-B at 64 CTAs and A-B-A at 128: global wins by about 24% at 64 CTAs, shared
  wins by about 16% at 128. The shared table wins at the measured best configuration, so it stays the
  default. The mechanism is UNKNOWN; L2 contention among 123 CTAs reading the global table is a
  hypothesis (INFERRED, low), left as follow-up research.

## General FORGE/Omega wins vs sieve-only

General (shared Omega GPU code; coverage limited to what was tested):
- C4 marker spin in the GPU session: about 97 us less per launch in the launch-cost tool (OBSERVED).
  Any short kernel that waits on the marker should gain the same (INFERRED); other workloads are not
  measured.
- C2b NAK-derived scheduling for every elementwise family, plus a fixed-RAW hazard checker. It passed
  all 31 existing elementwise kernel checks on the chip (OBSERVED). Speed effects on other Omega
  workloads are not measured. Predicate guard delay is now 14, the reference value, up from 13.
- C2a `ld_group` and the scoreboard hazard checker; C3's QMD shared-memory size support and the
  simulator's barrier and race model; the C1 finding that 1024-CTA launches work.
- The C5 lesson: the emitter has no reconvergence point, and lanes that take different paths can cost
  about 8x here. The general fix is structured reconvergence in the code generator, preserving program
  behavior, not a hand rewrite of every such loop. Filed as aien-dev/omega#308, with this sieve's
  original loop as a regression case beside other loop shapes (if/else, lane-dependent break, nesting,
  early exit before a barrier or shuffle). The attention kernel already hit the correctness side of the
  same gap on 2026-10-04.

Sieve-only: the C5 loop rewrite itself, the C3 staged kernel (default at limits up to 127,667,400;
after C5 it is the measured winner at 128 CTAs and the loser at 64, see C7), and the CTA budget value
for this grid.

## Limits

- Linux-hosted GB10, not AIENOS. One workload, one limit. The CUDA program mirrors our algorithm; it is a
  yardstick, not CUDA's best possible sieve.
- Both GPU paths are now launch-bound: native about 45 us submit-to-marker per pass, CUDA 35.8 us
  kernel-only (frozen receipt).
- C1 receipts carry the label `c7086da` on a binary that contains the `dea8b5c` code (stale-label build
  bug, fixed in omega `0dc96dc`; the strings differ only in the label). Every later step's labels are
  exact.
- Omega PR #307 (stacked on #303) holds the code. Nothing here is merged by this session.
